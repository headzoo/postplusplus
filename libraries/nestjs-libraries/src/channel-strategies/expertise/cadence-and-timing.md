# Cadence and timing

## Purpose / when to use

Use when choosing **how soon and how often** to follow up across relationship goals — audience growth, leads, retention, awareness, or support — with principle-based spacing, not rigid formulas.

## Evidence to verify

From current tool results, confirm:

- **Recency** of your last message and their last reply (or silence).
- **Channel norms** — public thread vs DM, professional vs casual context (from visible behavior, not assumptions).
- **Urgency** — real deadlines they care about vs artificial urgency you might impose.
- **Response state** — awaiting their reply, conversation active, issue open, or thread closed.
- Strategy goal for this relationship (grow, lead, retain, thank, support).

## Decision principles

1. **Active two-way thread** — respond in kind; do not flood while they are still engaging.
2. **Awaiting their reply** — allow a reasonable pause before one follow-up; add new value if you nudge again.
3. **Cooling or one-sided** — lengthen gaps; see `cooling-relationship-reengagement` and `over-invested-one-sided-cooling`.
4. **Support issues** — prioritize timely acknowledgment; resolution pace follows case severity, not marketing cadence.
5. **Thank-yous and mentions** — prompt but not instant; one acknowledgment per amplification event.

Spacing is **relative**: a day may be long in a hot support thread and short for a cold lead. Compare to their typical response time when data exists.

## Decision sequence

1. Read last interaction timestamps from tools.
2. Classify relationship state (active, waiting, cooling, closed, support).
3. Pick the next action type (reply, wait, single follow-up, re-engage, disengage).
4. If recommending a message, note **why now** is appropriate in one line tied to evidence.
5. Never bypass freshness — if tools show a reply just arrived, update before recommending another outbound.

## Avoid / stop conditions

- No universal "wait exactly N days" rules without context.
- No stacking messages because a score dropped — scores inform judgment, they do not auto-trigger spam.
- No ignoring platform rate limits or org policies implied by tool configuration.
- No cadence recommendations that override `when-not-to-engage` or confirmation requirements.

## Ground in tool results

Timestamps, thread state, and strategy directives from live data define timing. This playbook offers judgment; tools and server strategy set priorities.
